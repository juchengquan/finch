## §1. Glossary

The recurring terms + their canonical numbers, alphabetized.

### A

- **ActionName enum** — the iOS port's Swift enum; 74 cases (75 with
  Phase 6.5's `setEntryAttachment`). See
  `IOS_MACOS_WIRE_FORMAT.md` §2.4.
- **Adjust-account-balance action** — `adjustAccountBalance`
  (transactions domain). Args: `{ accountId, targetBalance, date?, note?, source? }`.
  See `IOS_MACOS_WIRE_FORMAT.md` §2.2.
- **Anomaly threshold** — `2.5` (the web's default in
  `lib/select.ts::anomalyScore`). See
  `IOS_MACOS_PHASE_6_2_DESIGN.md` §3.4.
- **App Group container** — `group.com.juchengquan.finch`. **Added
  in Phase 6.5's Xcode setup** (not Phase 5). See
  `IOS_MACOS_PHASE_6_5_DESIGN.md` §2.2.
- **Args enum** — the chokepoint's per-action input shape; 74
  cases mapped from `frontend/lib/db/domain/_args.ts`. See
  `IOS_MACOS_WIRE_FORMAT.md` §2.

### B

- **Bun test runner** — the web's test runner. The Phase 1.0
  fixture export script uses `bun:test` patterns. The iOS port
  uses XCTest (Swift). See `IOS_MACOS_PHASE_1_DESIGN.md` §8.4.
- **Bundle.module** — SwiftPM test target resource accessor. The
  Phase 1.5 parity test reads fixtures via
  `Bundle.module.url(forResource:withExtension:)`. The test
  target must declare `resources: [.copy("Fixtures")]`. See
  `IOS_MACOS_PHASE_1_5_DESIGN.md` §4.4.

### C

- **Chokepoint dispatcher** — `lib/db/mutate.ts` (53 lines); merges
  the 13 per-domain `handlers` maps into one `ALL` map. The
  iOS port mirrors this with `FinchStore.apply`. See
  `IOS_MACOS_PHASE_2_DESIGN.md` §2.
- **`CategoryEntity` (App Intents)** — `AppEntity` wrapping finch
  categories for Siri parameters. See
  `IOS_MACOS_PHASE_6_4_DESIGN.md` §3.
- **Cross-domain deps** — 5 known direct-`queries` imports in
  the per-domain `mutations.ts` files
  (`accounts → accountGroups`, `transactions → attachments`,
  `budgets → budgetGroups`, `rules → counterparties`,
  `scheduled → counterparties`). See
  `IOS_MACOS_PHASE_2_DESIGN.md` §6.

### D

- **`DBContext`** — iOS `Selectors` struct's `db: any
  GRDB.DatabaseReader` field. Used for narrow DB lookups in
  selectors that need rates or other DB-only data. See
  `IOS_MACOS_PHASE_1_5_DESIGN.md` §3.
- **Display currency** — per-ledger; persisted in
  `app_state['displayCurrencyByLedger']` as a JSON
  `{[ledgerId]: currency}` map (single key, not per-ledger
  keys). See `IOS_MACOS_WIRE_FORMAT.md` §2.2 (app_state).

### E

- **End-of-phase 8 audit-corruption fixtures** — 8 fixtures, one
  per `auditLedger` problem class. Generated by
  `frontend/scripts/export-fixtures.ts` (Phase 1.0 §8.4).
  See `IOS_MACOS_PHASE_1_DESIGN.md` §8.2.

### F

- **Fixtures format** — `SelectorFixture` JSON schema with
  `name`, `selector`, `input`, `expected`, optional `seed`.
  See `IOS_MACOS_WIRE_FORMAT.md` §5.
- **FTS5 search scope** — the `entries_fts` virtual table indexes
  only `description` + `notes` (not `counterparties.name` or
  `merchants.name`). See `IOS_MACOS_PHASE_1_DESIGN.md` §5 (Tab 2).
- **Force import** — the recovery hatch for non-audit-clean
  `.finch` files; **always visible** in **Settings › Advanced**
  (not behind `?debug=1`). See
  `IOS_MACOS_PHASE_1_DESIGN.md` §4.

### G

- **GRDB.swift** — the iOS port's SQLite library; version
  7.11.0 (per `IOS_MACOS_PLAN.md` §4.2). WAL mode +
  `synchronous=NORMAL`. `DatabasePool` for concurrent reads.

### H

- **Holdings tab** — the 7th write screen in Phase 2 (per Q32
  resolution). See `IOS_MACOS_PHASE_2_DESIGN.md` §7.8.

### I

- **I18nError** — the structured error pipeline. Wire shape:
  `{ code, params, message }`. See
  `IOS_MACOS_WIRE_FORMAT.md` §3.
- **iCloud conflict detection** — both signals (extended
  attribute primary + filename pattern fallback). See
  `IOS_MACOS_PHASE_5_DESIGN.md` §4.1.
- **iCloud folder watch** — `NSMetadataQuery` with
  `NSMetadataQueryUbiquitousDocumentsScope` +
  `NSPredicate(format: "kMDItemFSName LIKE[c] '*.finch'")`. See
  `IOS_MACOS_PHASE_5_DESIGN.md` §3.1.

### L

- **LedgerRow.base** — the field is `base: string` (NOT
  `baseCurrency`). The iOS port uses `.base`. See
  `IOS_MACOS_WIRE_FORMAT.md` §2.2 (ledgers note).
- **LEDGER_DOMAIN_PER_DOMAIN_FILES** — 13 per-domain
  `mutations.ts` files (out of 14 first-class domains;
  `attachments/` is queries-only). See
  `IOS_MACOS_PHASE_2_DESIGN.md` §2.

### M

- **MIGRATIONS array** — in `lib/db/core/schema.ts` (NOT
  `lib/db/core/entries.ts`). Defines per-version schema
  migrations. See `IOS_MACOS_PHASE_1_DESIGN.md` §4.
- **MIME type for attachments** — stored on the
  `entry_attachments.mime_type` column; converted to file
  extension via `UTType.preferredFilenameExtension` on iOS.
  See `IOS_MACOS_PHASE_6_5_DESIGN.md` §3.2.

### N

- **74 unique chokepoint actions** — the chokepoint's
  per-domain `handlers` maps produce 77 entries (3 duplicates
  in `accounts/`); 74 unique actions. **75 with Phase 6.5's
  `setEntryAttachment`**. See `IOS_MACOS_WIRE_FORMAT.md` §2.

### P

- **Pack format** — `.finch` packs are ZIP files containing
  `finch.sqlite3` (DEFLATE) + `attachments/<tx_id>/<att_id>.<ext>`
  (STORE) + `manifest.json` (DEFLATE). `pack_format_version = '1'`.
  See `IOS_MACOS_WIRE_FORMAT.md` §4.
- **Passcode fallback** — the iOS device passcode is the fallback
  via `LAContext.evaluatePolicy(.deviceOwnerAuthentication, ...)`;
  finch does NOT implement its own passcode fallback. See
  `IOS_MACOS_PHASE_6_3_DESIGN.md` §1.
- **Parity test harness** — JSON fixtures generated from the
  web's `select.test.ts`, run by the iOS SwiftPM test target. See
  `IOS_MACOS_PHASE_1_5_DESIGN.md` §4.

### S

- **Selectors module** — iOS port's Swift struct; the read-side
  brains. Phase 1.5 introduces it. 32 selectors total (7 in 1.0,
  25 in 1.5), grouped into 8 selector groups. See
  `IOS_MACOS_PHASE_1_5_DESIGN.md` §2.
- **`setEntryAttachment`** — the chokepoint's only new action in
  Phase 6.5; brings the running total to 75. See
  `IOS_MACOS_PHASE_6_5_DESIGN.md` §3.3.
- **Settings › Advanced** — collapsed section in the Phase 1.0
  Settings tab; contains the Force import button. See
  `IOS_MACOS_PHASE_1_DESIGN.md` §5.4.

### T

- **Tab list (Phase 1.0)** — 4 tabs: Accounts / Activity /
  Budgets / Settings. See
  `IOS_MACOS_PHASE_1_DESIGN.md` §5.
- **Tab list (Phase 1.5)** — 5 tabs (adds Insights). See
  `IOS_MACOS_PHASE_1_5_DESIGN.md` §1.
- **Tab list (Phase 2)** — 6 tabs (adds writable Scheduled;
  Reports is the 5th by display order, Settings is a section,
  not a tab). See `IOS_MACOS_PHASE_2_DESIGN.md` §7.6.

### W

- **Write screens (Phase 2)** — 7 screens: Add Transaction,
  Edit Transaction, Transaction Detail edits, Pending confirm,
  Budget CRUD, Scheduled CRUD, Ledger CRUD, plus the Holdings
  tab + CRUD UI. See `IOS_MACOS_PHASE_2_DESIGN.md` §7.

## §3. Master iPhone tab list

The canonical tab list at each phase, in display order. The mobile
tab bar shows them; the iPad sidebar and Mac sidebar show the same
list (per Phase 3 §2.1 size-class matrix).

### Phase 1.0 (4 tabs)

| # | Tab | Read-only? |
|---|---|---|
| 1 | Accounts | Yes (read-only list of accounts) |
| 2 | Activity | Yes (read-only transaction list) |
| 3 | Budgets | Yes (read-only progress bars) |
| 4 | Settings | No (interactive: active ledger, import, export) |

### Phase 1.5 (5 tabs)

Adds **Insights** as the 5th tab (between Budgets and Settings).

| # | Tab | Read-only? |
|---|---|---|
| 1 | Accounts | Yes |
| 2 | Activity | Yes |
| 3 | Budgets | Yes |
| 4 | **Insights** | **Yes (new in 1.5)** |
| 5 | Settings | No (interactive) |

### Phase 2 (6 tabs)

Adds **Scheduled** as the 6th tab (writable in Phase 2).
**Reports** is the 5th by display order (per the size-class matrix);
**Settings** is a section within the app, not a tab.

| # | Tab | Read-only? |
|---|---|---|
| 1 | Accounts | Yes (Phase 1.0) |
| 2 | Activity | Yes (Phase 1.0) |
| 3 | Budgets | Yes (Phase 1.0) |
| 4 | Insights | Yes (Phase 1.5) |
| 5 | **Reports** | **Yes (web has it; the iOS port may or may not have it — see Phase 2 §7.6)** |
| 6 | **Scheduled** | **No (writable in Phase 2)** |
| 7 | Holdings | Accessible via Accounts tab › [account] › Holdings section |

**iOS Settings** is reached via a gear icon in the top bar (not
a tab).

### Phase 3+ (adaptive shell)

Phase 3 wraps the tab list in `NavigationSplitView` for iPad + Mac;
the mobile tab bar on iPhone is unchanged.
