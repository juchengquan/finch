## How we work (conventions)

- **Flow per feature:** brainstorm → design spec → implementation plan → subagent-driven execution (one subagent per task, review between) → PR to `feat/frontend` → user merges → delete worktree/branch. Specs/plans live in `plans/ios-macos/<date>-<feature>-{design,plan}.md`.
- **Worktrees:** each feature in its own `git worktree` off `origin/feat/frontend` (e.g. `/tmp/finch-<slug>`); the user edits concurrently, so never stash/checkout in the main tree.
- **Commits:** **no `Co-Authored-By` trailer**. **Builds:** always FinchApp (iOS) **and** FinchMac (macOS); `xcodegen generate` after adding/removing files. **Engine tests:** `cd ios/FinchCore && swift test` — keep **ParityTests** green (additive selectors are safe; note `ListOptions` is decoded by the parity fixtures, so new non-optional fields need Codable defaults). FinchApp tests run via `xcodebuild test -only-testing:FinchAppTests` (not `swift test`).
- **CI:** docs-only PRs (`plans/**`, `*.md`) skip CI via `paths-ignore` (#278). iOS CI was ~halved (#276). **Note:** a PR can be merged while the long iOS check is still *pending* — confirm the iOS job goes green post-merge.
- **Sim verification — use `idb`, not AppleScript (2026-07-21).** `idb` drives the sim over its own companion socket with **no Accessibility permission**: `~/.local/idb-venv/bin/idb ui tap|swipe|describe-all --udid <UDID>`. Install: `brew install facebook/fb/idb-companion` + `fb-idb` in a **Python 3.11** venv (`fb-idb` calls `asyncio.get_event_loop()`, removed in 3.12+). `ui describe-all` returns the a11y tree with frames **in points** — measure layout with it instead of eyeballing screenshots. **AppleScript/AX cannot work under tmux**: TCC attributes `osascript` to the detached tmux server, so granting Accessibility to the terminal or ClaudeCode.app has no effect. Older caveat, still true for AX: **SwiftUI sheets/menus do not open under AppleScript AX automation** — the feed filter sheet and toolbar **Menu** popovers register the press but don't present (menu items live in a separate AX window). Verify those by hand, or lean on engine unit tests for the logic. Seed DB state + AXPress by accessibility description where possible; tappable rows/buttons on a visible screen do work. (The Settings **gear** moved to the top-left, #339.) As of #458, **FinchAppTests no longer overwrite the sim app's live DB** (tests run against `tmp/finch-tests/`), so manually-seeded/demo data survives test runs; and as of #457 the import fixture IS the demo dataset.
- **Add/edit sheet layout is tokenized (#554) — use the helpers, don't hand-roll.** New sheets: wrap the `Form` in **`finchSheetForm()`** (app-wide section gap + a pinned top margin) and label secondary sections with **`finchSectionHeader(_:)`** (takes a `LocalizedStringKey` — a `String` silently loses zh-Hans). Values live in `Common/Metrics.swift`: `sectionSpacing`, `sheetTopMargin`, `headerTopPadding`, `headerBottomPadding`, `captionInsets`. **Rule:** the type-caption section, the primary field group, and the error section stay **bare**; every secondary group gets a header; hints are always section **footers**, never an inline `Text` row. The type control comes from **`TxnTypeToolbar`** (`segmented`/`locked`/`caption`) — Budget hand-rolled a byte-identical copy before #554. **Gotcha:** SwiftUI does *not* give these sheets a consistent top inset — `AddTransactionSheet` carried a hardcoded `.contentMargins(.top, 6)` one-off that left every other sheet **29pt lower**; `finchSheetForm()` generalizes it, so don't re-add per-sheet margins.
- **Dates are civil-date strings (#570) — one convention, never mix calendars.** A `yyyy-MM-dd` value is a day on the *user's* calendar, not an instant: parse/format with **`AppDate.isoDay`** and do component math with **`AppDate.civil`** (Gregorian, device zone). **Never hand-roll a hardcoded-UTC `Calendar` in the app layer** — parsing locally then reading UTC components shifts the day for every non-UTC user (it put `wallToday` a day behind before 08:00 at UTC+8 and rendered the Scheduled header one day early). `FinchCore` and `scheduledNextRun`/`resumeOccurrence` *are* internally UTC and that's fine: they parse, compute, and format inside one calendar and return a string, so the zone is unobservable — the bug is only ever at a `Date`↔string boundary. `FinchAppTests/CivilDateTests` guards it (fails in any non-UTC zone if a UTC-pinned converter returns). Full write-up in `ios/CLAUDE.md`.
- **A posted scheduled transaction carries `entries.occurrence_date` (#582) — resolution keys on `occurrenceDate ?? date`.** `Selectors.scheduledPostedMap` (Swift) and `lib/select.ts` (web, the extracted pure seam) both key the posted-map on the occurrence a transaction *fulfils*, not the day it was recorded, so posting a missed item on a later date still flips the right calendar badge; the NULL fallback makes every pre-existing row resolve exactly as before (no backfill). `generateDueScheduled` must dedup on **`COALESCE(occurrence_date, date)`** to match — a `SELECT date` dedup double-counts a late-posted occurrence (#582's `6c62576`). A bare "Post now" with no cell in hand resolves via **`Selectors.resumeOccurrence`** (oldest unresolved first, then next ≥ today); on the *silent* path a future-resolved occurrence is **refused** (it would book unconfirmed future income), while the calendar's explicit tap and the confirm-sheet are exempt. **The `AddTransactionSheet` link-forward is gated on an explicit `postsScheduledOccurrence` flag, NOT on `prefill?.sourceTemplateId != nil`** — the latter would make **Duplicate** claim the source's occurrence (flip a badge + eat an installment slot).
